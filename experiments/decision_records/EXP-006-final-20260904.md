# EXP-006：local exact 与 Qdrant/HNSW 向量后端对照

- 日期：2026-09-04
- 数据集：冻结 Master-200，4 个冻结仓库，200 个案例，其中 192 个有期望 Evidence
- Chunk：`fixed-80-00`
- Embedding：真实 `qwen3.7-text-embedding`；两个后端复用同一批索引向量和查询向量
- Chat 调用：0

## 结果

| 指标 | `local_json` exact | `qdrant_hnsw` |
| --- | ---: | ---: |
| Complete Evidence Coverage | 0.7917 | 0.7917 |
| Evidence Recall | 0.9070 | 0.9070 |
| MRR | 0.90139 | 0.90139 |
| Citation Validity | 1.0 | 1.0 |
| 查询 P95 | 0.449s | 0.296s |

Qdrant 参数为 `M=16 / efConstruction=128 / efSearch=64`。在这组固定查询中，质量和 Evidence 映射与 exact 相同，P95 观测更低；这不是 ×10 规模或参数最优性证明。

## 工程验收

- `VectorStore` 统一 `upsert/search/delete/health` 契约。
- Qdrant payload 包含 `repoId/path/language/startLine/endLine/symbol/module/sourceFingerprint/chunkVersion/visibility`。
- `SemanticIndex` 根据 point ID 恢复源码块，Qdrant payload 不直接充当 Evidence 文本。
- `IndexPublisher` 提供 staging → validate → publish → rollback 原子指针；无效 staging 不改变 active。
- `FallbackVectorStore` 只有在调用方显式组合时启用；主后端健康检查或操作失败时记录 `last_backend` 与 `last_reason`，再回退 local exact。

## 边界与后续

当前默认行为仍保持 local/in-process exact，Qdrant 是可注入的成熟后端路径；这避免在没有公开配置和 ×10 规模数据前改变现有产品默认。Qdrant/HNSW 的规模交叉点、M/ef 参数小矩阵和真实服务 Trace 后端移交后续规模化/可观测性步骤。
